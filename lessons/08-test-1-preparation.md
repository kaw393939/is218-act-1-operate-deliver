## The problem: can you own the workflow without generated repair?

The official test measures a bounded independent build–test–deliver task. It is not a speed contest for recreating every textbook command, and a green materials workflow is not proof of application behavior.

## Before assessment day

Read [the complete public Test 1 preparation specification](../assessments/test-1.md). Rehearse [the practice brief](../assessments/practice-brief.md) in a fresh personal repository. Compare your result with the earlier arithmetic references only after your attempt.

The practice and official test target the same workflow; the official handout may change operands, test case labels, repository name, and small arithmetic details. Do not memorize six answers or assume the public practice prompt is the official prompt. The instructor supplies the actual assessment repository and all permitted resources before starting.

## 80-minute assessment meeting

| Minutes | Activity |
| --- | --- |
| 0–5 | Read official scope/resources, confirm repository and access |
| 5–70 | Individual execution: build, write tests, commit and verify (65 minutes) |
| 70–80 | Publish final state, record full SHA/run identity, hand off |

No AI or peer assistance during the individual assessment. Disable AI completion. The practice specification permits this book's command reference; the official handout controls final resources and institutional accommodations. Report access failures to the instructor promptly.

## What you should be ready to explain

- Why the selected interpreter is the project interpreter.
- How one independently expected test can expose a wrong function result.
- Which files a focused commit includes and where it is published.
- Which exact revision the workflow executed.
- What the green run cannot prove.

These are visible preparation criteria, not additional surprise tasks. Assessment evidence and points are described in the preparation specification.
