# AI assistance and collaboration

[Act home](../README.md)

The goal is to direct tools with enough understanding to judge their work. You need both tool independence and guided experience managing AI.

**During direct-practice blocks:** personally type the terminal/Git operations and designated functions/tests. Pause AI generation and repair, including inline AI completion. Command references, ordinary syntax highlighting, instructor guidance, and explicitly assigned peer checks are allowed. Individual tests have stricter boundaries.

**During critique blocks and weekly work outside those blocks:** AI may explain an error or critique a bounded change. Read proposed commands before execution; inspect the diff and test an independent expectation. Log the question, one accepted/rejected recommendation, and the check you actually performed. A full generated submission cannot replace the required individual checkpoints.

Useful prompt: “Explain the difference between the working-tree diff and staged diff. Ask me to predict my next command before suggesting it.” Another: “Review this test against the stated contract. Identify what it fails to establish.” Check the answer against the repository and official references.

For pair work, both students author and review. A navigator describes the next check; a driver operates the tools. Rotate after one checkpoint. Use specific review language: “This checks two positive operands; add a mixed-sign case so we can test the negative-input contract.” Record actual review and response; never claim a self-review was a peer review.

**Test 1:** individual, no AI, no peer assistance. The supplied course command reference is allowed under the practice specification; the official handout announces the final allowed resources before the test. Disable AI completion before assessment. Institution accommodations and instructor instructions control timed conditions.

Evidence is about decisions and checks, not typing speed, code volume, or number of commits.
